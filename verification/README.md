# Verification evidence

The publication checks are recorded in `publication-verification.json`, `publication-build.log` and `publication-axioms.log`. The complete library, challenge and solution build successfully. The proof audit covers every declaration in all 92 proof modules, including the shared definitions, comparator solution, two-way statement-equivalence proofs and private/generated helpers: 2,056 declarations with only `propext`, `Classical.choice` and `Quot.sound` in their transitive axiom closure.

`challenge.lean` is a separate specification using transparent shared definitions from `ChallengeDefinitions.lean`, which imports only Mathlib with exactly two intentional theorem placeholders. It is never imported into `solution.lean` or `AllAxioms.lean`. Those placeholders are excluded from the proof-development counts. The authenticated source manifest includes the challenge, shared definitions, solution, equivalence file, comparator configuration, metadata and CI configuration. The verifier requires that its probe covers the entire library, shared definitions, solution and equivalence proofs, and rejects unlisted proof modules. Negative-control receipts record those rejection checks.

`comparator-local.json` and `comparator-local.log` record the actual official comparator run at the revision matching Lean 4.34.0-rc2. Both theorem statements match; permitted-axiom checks pass; the Lean default kernel accepts the solution. This local macOS run used upstream's development launcher without the Linux sandbox. The separate GitHub Actions job uses a fresh checkout, real Landrun and the documented AF_UNIX restriction. Local success does not assert a successful remote CI run; consult the repository's Actions page for current remote status.

`metadata-validation.json` records validation of `formalization.yaml` against the official version 0.4 schema. `comparator-semantic-audit.json` records the independent statement review, including the shared Mathlib-based definitions and unchanged quantifiers, witnesses and conclusions. `ChallengeEquivalence.lean` proves both compact propositions equivalent to the previous fully expanded statements without using either principal theorem.

Earlier full-owned-declarations, standalone and component records are preserved as history of the original 89-module, 2,021-declaration library before the comparator solution was added. The original library source files are unchanged. Component records used a non-internal root enumeration; the final exhaustive audits also cover private and generated roots. Dependency sources are pinned, existing Mathlib cache artifacts were reused locally, and caches are excluded from the repository.

The semantic and paper-coverage audits distinguish all proved results from external classifications, announcements, open problems and an unnecessary planning abstraction. The source snapshot and its editorial revision are documented in provenance/. Jury records remain separate from Lean verification: timeouts are abstentions, packaging findings and their resolutions remain visible, and no globally clean model-jury result is claimed.
